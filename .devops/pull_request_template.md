# API Playground - Pull Requests

Find below some useful information for creating a new pull request.

## Checklist 

Review the following points before creating a new pull request:

### ✅ Quality Checklist
- Code is self-documenting (no unnecessary comments)
- PR title ≤50 chars (Conventional Commits)
- Tech preferences applied (Minimal API, NSubstitute, etc.)
- Tests added/updated and passing
- Docs updated
- No secrets committed

### 🧪 Testing Checklist
- Unit tests cover new scenarios
- Integration tests verify workflows
- Edge cases considered and tested
- All tests pass locally

## Description template

Use the following template in the description of the pull request.

### 📝 Description
Clear summary of changes (what + why, not implementation details)

### 🎯 Type of Change

Check all the corresponding types:

- [ ] Feature 
- [ ] Bug Fix 
- [ ] Refactor 
- [ ] Performance 
- [ ] Docs 
- [ ] Build/Config 
- [ ] Breaking

### 🔄 Changes Overview

- What changed
- Why (aligned with standards)
- Key decisions

### 🔗 Related Links & Context

- Issue/work item
- Agent guidance used
- Architecture docs (if relevant)
- Breaking changes (if any)

### 📋 Notes for Reviewers

Highlight areas needing careful review, risk level (Low/Medium/High), or non-obvious decisions.
